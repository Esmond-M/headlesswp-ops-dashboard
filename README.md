# HeadlessWP Ops Dashboard

A portfolio-focused headless WordPress operations dashboard built with React, TypeScript, and Vite.

## Purpose
This app demonstrates practical headless CMS workflows:
- editorial queue management
- portfolio completeness scoring
- SEO/content audit checks

The dashboard uses the local WordPress installation `e-headlesswp` as its content source during development.

## Repositories

| Repository | Responsibility |
| --- | --- |
| `headlesswp-ops-dashboard` | React/TypeScript frontend and dashboard UI |
| `em-client` | WordPress theme integration, CPTs, taxonomies, metadata, and seed tooling |

The WordPress integration is developed on the `feature/headless-ops` branch.

## Stack
- React + TypeScript + Vite
- React Router
- TanStack Query
- Zod
- Recharts

## Local Development
```bash
npm install
npm run dev
```

Default app URL:
- http://localhost:5173

## WordPress Backend Setup
This app reads content from the `em-client` WordPress theme integration. The backend is local during development and remote for production.

See full checklist:
- WORDPRESS_BACKEND_SETUP.md
- [docs/react-app-page-deployment.md](docs/react-app-page-deployment.md) - Build and deploy the app into the parent theme

The theme provides the `project_item` Case Study CPT, `project_type` and `project_stack` taxonomies, REST-enabled metadata, Classic Editor support, an admin seed generator, and WP-CLI smoke tests.

After activating the theme, save **Settings > Permalinks** once so WordPress refreshes rewrite rules.

With Local running, the backend smoke test can be run from a terminal:

```bash
wp --path="C:\\Users\\PC\\Local Sites\\e-headless-wp\\app\\public" headless-ops test
```

## WordPress Environments
The dashboard supports separate local and production WordPress backends:

| Mode | WordPress origin | Usage |
| --- | --- | --- |
| Development | `http://e-headless-wp.local` | `npm run dev` |
| Production | `https://ops.esmondmccain.com` | `npm run build` and deployment |

The local app requests `/wp-json/wp/v2` through the Vite proxy. The production build uses `VITE_WP_ORIGIN` directly. Environment values are defined in `.env.local` or `.env.production`; use `.env.example` as the template.

To test the production backend from the local Vite server:

```bash
npm run dev -- --mode production
```

This keeps the app at `http://localhost:5173` while proxying its WordPress requests to `https://ops.esmondmccain.com`.

## Scripts
- npm run dev
- npm run lint
- npm run build
- npm run preview
These commands also appear in VS Code under **NPM Scripts**:

| Command | Use |
| --- | --- |
| `npm run dev` | Start Vite for local browser development |
| `npm run dev:host` | Start Vite and expose it on the local network |
| `npm run lint` | Check ESLint rules |
| `npm run test` | Run the frontend unit test suite once |
| `npm run test:watch` | Re-run tests while files change |
| `npm run test:coverage` | Run tests with coverage reporting |
| `npm run typecheck` | Run the TypeScript compiler without emitting app files |
| `npm run build` | Type-check and create the production `dist/` folder |
| `npm run check` | Run lint, tests, typecheck, and build together |
| `npm run preview` | Preview the latest production build locally |

Recommended end-of-day check:

```bash
npm run check
```

Frontend unit tests live beside the business logic in `src/lib/` and cover Case Study scoring, content audit rules, WordPress entity decoding, and CSV escaping.

## dist Folder

The `dist/` folder is generated by Vite when `npm run build` runs. It contains static deployment output such as `index.html` and versioned files in `dist/assets/`.

It is ignored by Git because it can be regenerated. Do not edit files inside `dist/` directly or commit it unless a hosting workflow specifically requires it.

For the current parent-theme deployment, copy the built runtime files into `esmond-theme/react-projects/headless-ops-app/` and update `esmond-theme/page-123457117.php` with any new hashed JavaScript or CSS filenames. See [docs/react-app-page-deployment.md](docs/react-app-page-deployment.md) for the complete procedure.

## Incremental Workflow

Commit one focused change at a time:

```bash
npm run check
git status
git add <files>
git commit -m "feat: describe the focused change"
```

Keep frontend changes, WordPress changes, and generated build files in separate commits where practical.
